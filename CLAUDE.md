# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Emergency parachute deployment system for the DJI Matrice 400 drone (9.74 kg with batteries, MTOW 15.8 kg). Detects free-fall via IMU and triggers a spring-loaded parachute mechanism. The system is **independent of the drone's flight controller**.

## Key Architecture

### Hardware Design (KiCad)
- The KiCad project (KiCad 10) lives in `hardware/paracaidas-matrice400/`. The v3 schematic (fully wired, power symbols, no floating labels) and the initial PCB placement were generated by Claude at the user's request; the user refines them in the KiCad GUI. There is no code-generation script in the repo.
- PCB: 2 layers, 90×62 mm, netclasses `Default` (0.3 mm) and `Power` (0.6 mm — limited by the MT3608 SOT-23-6 pad pitch; GND, +5V, VBAT, SW_NODE, SOL_DRV, BAT+) defined in the `.kicad_pro`. Routed with Freerouting 2.1 (2 vias) plus GND pours on F.Cu and B.Cu; DRC clean (0 violations, 0 unconnected, 0 parity issues). After moving parts, refill zones (B) and re-run DRC.
- The **authoritative design spec and netlist** is [docs/esquematicos/esquematico.md](docs/esquematicos/esquematico.md): full component table, ASCII schematic, pin-by-pin netlist, oscillator config, and design notes. Treat that document as the source of truth for connectivity.
- References in the `.kicad_sch` match the doc 1:1. Any connectivity change must be made in **both** the doc and the schematic then re-run ERC. Then update the PCB from the schematic (F8) and re-route the affected nets.

### System Blocks

| Block | Components | Rails |
|---|---|---|
| Power — LDO 3.3V | BT1 (LiPo 1S) → SW1 → MCP1700 (U3), C6 1µF in / C2 10µF out | 3.3V for PIC + IMU |
| Power — Boost 5V | MT3608 (U4), L1 22µH, Schottky D4 SS34, R8 750kΩ / R9 100kΩ, C5 22µF in / C4 100µF out | 5V for solenoid + buzzer |
| MCU | PIC18LF25K22 (U1), 28-SPDIP, internal oscillator 64 MHz | 3.3V |
| IMU | GY-521 module (MPU-6050) on header J3, I2C @ RC3/RC4 (module's own 4.7k pull-ups), INT → RB0 | 3.3V |
| Deployment actuator | Solenoid 5V (SOL1 on J4) driven by AO3400A MOSFET (Q1), flyback D1 (1N4007) | 5V |
| Parachute mechanism | Spring tube; mechanical latch holds unpowered, solenoid **pulse (~300 ms) releases** | mechanical |
| Indicators | LED1 green (RA0), LED2 red (RA1), Buzzer via 2N3904 Q2 (RC0) | — |
| Debug/Programming | J1 = UART (RC6/RC7), J2 = ICSP PICKit (RB6/RB7) | — |

### Parachute Canopy
- Type: circular **Ripstop Nylon 30D sil-nylon**, **3.5 m diameter**, 12 gores (Cd ≈ 0.75, descent ≤6 m/s at 16 kg = MTOW 15.8 kg + system)
- Sizing formula: `Area = (2·m·g) / (Cd·ρ·v²)` = 313.9 / 33.08 ≈ 9.5 m² → Ø3.5 m. (An earlier 0.82 m² / Ø1.2 m figure was an arithmetic error; Ø1.2 m gives 14–17 m/s.)
- Minimum useful deployment altitude ~20–40 m (detection + release + inflation ≈ 1.5–2.5 s). The system does not cut the motors, so ejection must clear the propeller plane.
- Mechanism: **spring tube** — latch holds with solenoid OFF; a ~300 ms solenoid pulse pulls the pin and the spring ejects the parachute (~50–100 ms). Reset/brown-out never deploys (R2 keeps Q1 off).
- Sources: Fruity Chutes, Mars Parachutes (models rated for 15–16 kg)
- Details in `docs/investigacion/modulos.md`

### Free-fall Detection Logic
- Threshold: `|√(ax²+ay²+az²)| < 0.3g` sustained for >100 ms
- Integer math only (PIC18 has no FPU)
- First-order IIR filter to reject motor vibration
- MPU-6050 I2C address: 0x68 (AD0 tied to GND)

### PIC18LF25K22 Configuration Bits
```c
#pragma config FOSC    = INTIO67   // Internal oscillator, RA6/RA7 as GPIO
#pragma config PLLCFG  = ON        // PLL x4 → 64 MHz
#pragma config MCLRE   = EXTMCLR  // MCLR pin enabled (SW2 reset)
#pragma config LVP     = OFF
#pragma config WDTEN   = OFF       // Enable in production
```

## Working with the KiCad Schematic

- **Source of truth**: [docs/esquematicos/esquematico.md](docs/esquematicos/esquematico.md) (component table, net table, design notes). Keep that doc, the `.kicad_sch` and this file consistent.
- After any schematic/PCB change, verify with `kicad-cli` (netlist export, ERC, DRC with `--schematic-parity`) (`kicad-cli` is at `C:/Program Files/KiCad/10.0/bin/kicad-cli.exe`).
- **5V output voltage**: set by `Vout = 0.6 × (1 + R8/R9)` = 0.6 × 8.5 = **5.1V**
