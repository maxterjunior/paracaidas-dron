# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Emergency parachute deployment system for the DJI Matrice 400 drone (9.74 kg with batteries, MTOW 15.8 kg). Detects free-fall via IMU and triggers a spring-loaded parachute mechanism. The system is **independent of the drone's flight controller**.

## Key Architecture

### Hardware Design (KiCad)
- The KiCad project (KiCad 10) lives in `hardware/paracaidas-matrice400/`. The v4 schematic (fully wired, power symbols, all SMD, `LCSC` field on every part) and the routed PCB were generated by Claude at the user's request; the user refines them in the KiCad GUI. There is no code-generation script in the repo. Project libraries: `paracaidas.kicad_sym` (`BMI088_I2C`: BMI088 with SDO1/SDO2 as inputs so ERC accepts them tied to GND) and `paracaidas.pretty` (`Buzzer_MLT-9650`, pads taken from the LCSC/EasyEDA footprint).
- PCB: 2 layers, 60×40 mm, all parts on top, 4 M3 holes. Netclasses in the `.kicad_pro`: `Default` 0.2 mm / 0.15 mm clearance (SSOP-28 0.65 mm and LGA-16 0.5 mm pitch) and `Power` 0.6 mm (+5V, VBAT, SW_NODE, SOL_DRV, BAT+). GND is not in `Power`: it goes through pours on F.Cu and B.Cu (0.6 mm tracks cannot reach fine-pitch GND pins). The BMI088 footprint forbids F.Cu under the sensor, so its +3V3/GND pins have a locked manual fanout (0.15 mm stubs, 0.5/0.25 mm vias, +3V3 joined on B.Cu). Routed with Freerouting 2.1; DRC clean (0 violations, 0 unconnected, 0 parity issues). After moving parts, refill zones (B) and re-run DRC.
- JLCPCB outputs live in `hardware/paracaidas-matrice400/jlcpcb/` (gerbers, `bom_jlcpcb.csv`, `cpl_jlcpcb.csv`). Regenerate them after any PCB change, and also rebuild `paracaidas-matrice400-gerbers.zip` (gitignored, for upload). Every part has an LCSC number, connectors included. J1 uses `PinHeader_1x03_..._SMD_Pin1Left` and J2 `PinHeader_1x06_..._SMD_Pin1Right` to match the pin-1 side of the LCSC headers (C41417360 / C41417363).
- The **authoritative design spec and netlist** is [docs/esquematicos/esquematico.md](docs/esquematicos/esquematico.md): full component table, ASCII schematic, pin-by-pin netlist, oscillator config, and design notes. Treat that document as the source of truth for connectivity.
- References in the `.kicad_sch` match the doc 1:1. Any connectivity change must be made in **both** the doc and the schematic then re-run ERC. Then update the PCB from the schematic (F8) and re-route the affected nets.

### Parachute Canopy
- Type: circular **Ripstop Nylon 30D sil-nylon**, **3.5 m diameter**, 12 gores (Cd ≈ 0.75, descent ≤6 m/s at 16 kg = MTOW 15.8 kg + system)
- Sizing formula: `Area = (2·m·g) / (Cd·ρ·v²)` = 313.9 / 33.08 ≈ 9.5 m² → Ø3.5 m. (An earlier 0.82 m² / Ø1.2 m figure was an arithmetic error; Ø1.2 m gives 14–17 m/s.)
- Minimum useful deployment altitude ~20–40 m (detection + release + inflation ≈ 1.5–2.5 s). The system does not cut the motors, so ejection must clear the propeller plane.
- Mechanism: **spring tube** — latch holds with solenoid OFF; a ~300 ms solenoid pulse retracts the plunger, the latch lever swings out and the spring ejects the parachute (~50–100 ms). Reset/brown-out never deploys (R2 keeps Q1 off).
- Sources: Fruity Chutes, Mars Parachutes (models rated for 15–16 kg)
- Details in `docs/investigacion/modulos.md`

### Mechanism (hardware/mecanismo/)
- **Source of truth**: `mecanismo.scad` (OpenSCAD, parametric, mm, Z up, tube axis on Z). Select a part with `-D 'pieza="..."'`. Printable: `base tubo piston tapa collar palanca caja tapa_caja adaptador`; reference only: `resorte solenoide embolo paracaidas dron helices`; `conjunto` / `mecanismo` = assemblies. Parts are exported in assembly position (orient them in the slicer).
- Layout: tube Ø100 ID × 280 mm (~1.6 L), bottom at z = 10, mouth at `zt` = 290. Spring Ø90 compressed to 45 mm. Lid hinged at `bis` (−X side), latch on +X: lid tab with a window, `palanca` (lever) pivoting at `piv`, solenoid plunger along Y at `emb`.
- Latch principle: the spring load acts 2.7 mm inboard of the lever pivot, so the lever tends to open outward and the plunger only blocks it sideways (shear, a few N). Unpowered = plunger extended = locked. Keep this geometry if you move parts, or a small solenoid will no longer release it.
- Provisional values (must be measured): solenoid `sol_*` (modeled as JF-0530B 5 V), M400 mount pattern `montaje_*`, drone envelope `dron_*` / `helice_*`. The bridle must anchor to the drone frame, never to printed parts.
- After changing the `.scad`:
  1. Re-export the printable STLs to `hardware/mecanismo/stl/`.
  2. Check interferences: `intersection()` of two parts in assembly position must export as an empty object (OpenSCAD reports "empty"); a zero-thickness result is only contact. Also check the moving parts: lid rotated about `bis` 0–118°, lever rotated 22° about `piv`, plunger retracted (`embolo(true)`).
  3. Regenerate the viewer with `python hardware/mecanismo/visor/empaquetar.py <openscad.com>`.
- OpenSCAD is not installed on this machine; it was run from a portable 2021.01 copy in a session scratchpad (gone later). Ask the user to install it (`winget install OpenSCAD.OpenSCAD`) or to allow a portable copy.
- **Viewer** (`visor/`): `index.html` (three.js 0.128) loads the parts from `piezas.js` (binary STLs in base64, generated by `empaquetar.py`; Claude artifacts do not serve `.stl`, and this also lets `index.html` open without a server). The animation constants `zt`, `BIS`, `PIV`, `EMB`, `PISTON0` are duplicated in `index.html` and must match the `.scad`. PCB, battery, pins and the inflated canopy are drawn procedurally, not from the CAD.
- The viewer is published as a Claude artifact linked from the README: https://claude.ai/artifact/HH7TuvKMzHhvBDsvPzRwz9 (shared with anyone with the link). Republish to that same URL with `index.html` as the page and `piezas.js` as a file, with `root` = `hardware/mecanismo/visor`.

### Detection Logic (firmware/src/detector.c)
- Only fires when ARMED. Armed = motor vibration (high-frequency accel content) ≥ `VIB_ARM_MG` for 5 s; disarms after 10 s without vibration. Never arms in the first 10 s.
- Criteria (any): free fall `|a| < 300 mg` for 100 ms; tumble `|ω| > 250 °/s` for 300 ms; tilt > 70° from the up axis (or inverted) for 500 ms.
- Integer math only (PIC18 has no FPU); first-order IIR filters; 500 Hz sampling.
- BMI088 I2C addresses: accelerometer 0x18 (±12 g), gyroscope 0x68 (±1000 °/s). Thresholds live in `firmware/src/app_config.h`; those marked AJUSTAR must be calibrated with real flight logs.
- Still missing: manual RC trigger (free pin RB2/INT2).

### PIC18F25K22 Configuration Bits (firmware/src/config_bits.c)
- `FOSC = INTIO67`, `PLLCFG = OFF`: internal 16 MHz, **no PLL** (avoids depending on the F part's Fmax at 3.3 V).
- `BOREN = SBORDIS`, `BORV = 250`; `WDTEN = SWON` (enabled in `main`, ~1 s); `MCLRE = EXTMCLR`; `LVP = OFF`; `PBADEN = OFF`.

## Working with the KiCad Schematic

- **Source of truth**: [docs/esquematicos/esquematico.md](docs/esquematicos/esquematico.md) (component table, net table, design notes). Keep that doc, the `.kicad_sch` and this file consistent.
- After any schematic/PCB change, verify with `kicad-cli` (netlist export, ERC, DRC with `--schematic-parity`) (`kicad-cli` is at `C:/Program Files/KiCad/10.0/bin/kicad-cli.exe`).
- **5V output voltage**: set by `Vout = 0.6 × (1 + R8/R9)` = 0.6 × 8.5 = **5.1V**

## Firmware
- v0.1.0 in `firmware/` (PIC18F25K22, MPLAB XC8, C99). **Not compiled or tested on hardware yet** (no XC8/gcc on this machine); the detector logic was checked with a Python port of the same test cases. See `firmware/README.md`.
- `src/`: `main.c` (state machine FALLA/DESARMADO/ARMADO/DESPLEGADO, solenoid pulses, LEDs/buzzer, UART log), `detector.c` (pure C, host-testable), `app_config.h` (thresholds), `board.c/.h` (pin map), `config_bits.c`.
- `lib/hal/`: Timer2 1 ms tick, MSSP1 I2C with timeouts and bus recovery, EUSART1 115200 (`putch` for printf), ADC with FVR 2.048 V for VBAT. `lib/bmi088/`: driver.
- `__persistent` variables: a reset during the solenoid pulse re-fires on boot; a reset while ARMED returns straight to ARMED.
- Build: `make` (xc8-cc), `make BENCH=1` (UART bench commands ARM/DISARM/FIRE — never fly it), `make test` (gcc).
